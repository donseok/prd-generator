# 시스템 모니터링 웹 대시보드 PRD (Product Requirements Document)

**버전**: 1.0
**작성일**: 2026-03-24
**상태**: Draft

---

## 1. 개요

### 1.1 배경
현대 IT 인프라 운영에서 시스템 리소스의 실시간 모니터링은 안정적인 서비스 운영의 핵심입니다. 서버의 CPU, 메모리, 디스크, 네트워크 상태를 실시간으로 파악하지 못하면 장애 대응이 지연되고, 성능 병목 현상을 사전에 감지하기 어렵습니다.

본 프로젝트는 웹 기반의 실시간 시스템 모니터링 대시보드를 개발하여, 운영자가 브라우저만으로 시스템 리소스 상태를 직관적으로 파악할 수 있도록 합니다. Python psutil 라이브러리를 활용한 백엔드 데이터 수집과 React+Recharts 기반의 프론트엔드 시각화를 결합하여, 3초 간격의 실시간 모니터링 환경을 제공합니다.

### 1.2 목표
- 4종 시스템 리소스(CPU, 메모리, 디스크, 네트워크)를 실시간 대시보드로 시각화
- 3초 간격 자동 갱신으로 준실시간 모니터링 환경 제공
- 다크 테마 기반의 직관적이고 반응형인 대시보드 UI 구현
- 분석→설계 단계를 2026-04-01부터 2026-05-07까지 완료

### 1.3 범위
#### 포함 범위
- CPU 사용률 실시간 라인 차트
- 메모리 사용률 실시간 라인 차트 (전체 대비 사용량)
- 디스크 사용량 파이 차트 (드라이브별)
- 네트워크 IN/OUT 트래픽 실시간 차트
- 3초 간격 자동 갱신 메커니즘
- 다크 테마 UI, 반응형 그리드 레이아웃
- 백엔드 API (Python + psutil)
- 프론트엔드 대시보드 (React + Recharts)

#### 범위 외
- 알림/경고 시스템 (이메일, SMS, Slack 알림)
- 히스토리 데이터 저장 및 조회 (DB 연동)
- 다중 서버 모니터링 (원격 에이전트)
- 사용자 인증 및 권한 관리
- 로그 모니터링 및 분석
- 프로세스별 리소스 사용량 상세 분석

### 1.4 대상 사용자
| 사용자 유형 | 역할 및 주요 활동 |
|------------|------------------|
| 시스템 운영자 | 서버 리소스 상태를 실시간으로 모니터링하고 이상 징후를 감지 |
| 개발자 | 개발/테스트 환경의 리소스 사용 현황을 확인하며 성능 최적화에 활용 |
| 인프라 관리자 | 서버 용량 계획 수립을 위한 리소스 사용 추이 파악 |

### 1.5 성공 지표
- 대시보드 로딩 시간 2초 이내
- 데이터 갱신 주기 3초 준수율 99% 이상
- CPU/메모리/디스크/네트워크 4종 리소스 시각화 100% 구현
- 반응형 레이아웃 지원 (데스크톱, 태블릿)

## 2. 기능 요구사항 (Functional Requirements)

### FR-001: CPU 사용률 실시간 모니터링
**우선순위**: HIGH
**설명**: 시스템 전체 CPU 사용률(%)을 실시간 라인 차트로 표시한다. 시간축 기반의 트렌드 시각화를 통해 CPU 사용률 변화 추이를 파악할 수 있다.

**User Story**: 시스템 운영자로서, 나는 CPU 사용률을 실시간 라인 차트로 보고 싶다, 서버 부하 상태를 즉시 파악하기 위해.

**Acceptance Criteria**:
- [ ] CPU 사용률(%)이 라인 차트로 표시된다
- [ ] 시간축(X축)과 사용률(Y축, 0~100%) 기반 차트가 렌더링된다
- [ ] 3초 간격으로 새 데이터 포인트가 추가된다
- [ ] 최근 N분간의 트렌드가 시각화된다

**출처**: 요청사항.md > 모니터링 항목 > 1. CPU 사용량

### FR-002: 메모리 사용률 실시간 모니터링
**우선순위**: HIGH
**설명**: 시스템 메모리 사용률(%)을 실시간 라인 차트로 표시한다. 전체 메모리 용량 대비 현재 사용량을 함께 표시하여 직관적인 리소스 파악이 가능하다.

**User Story**: 시스템 운영자로서, 나는 메모리 사용률과 전체 대비 사용량을 실시간으로 보고 싶다, 메모리 부족 상황을 사전에 감지하기 위해.

**Acceptance Criteria**:
- [ ] 메모리 사용률(%)이 라인 차트로 표시된다
- [ ] 전체 메모리 대비 사용량(예: 8.2GB / 16GB)이 함께 표시된다
- [ ] 3초 간격으로 자동 갱신된다
- [ ] 시간축 기반 트렌드 시각화가 제공된다

**출처**: 요청사항.md > 모니터링 항목 > 2. 메모리 사용량

### FR-003: 디스크 사용량 시각화
**우선순위**: HIGH
**설명**: 디스크 사용량과 잔여 공간을 파이 차트로 시각화한다. 각 드라이브(파티션)별 사용량을 개별적으로 표시한다.

**User Story**: 시스템 운영자로서, 나는 디스크 사용/잔여 공간을 파이 차트로 보고 싶다, 디스크 용량 부족을 사전에 방지하기 위해.

**Acceptance Criteria**:
- [ ] 디스크 사용/잔여 공간이 파이 차트로 표시된다
- [ ] 각 드라이브(파티션)별 사용량이 개별적으로 시각화된다
- [ ] 사용률(%), 사용 용량, 전체 용량이 표시된다
- [ ] 3초 간격으로 갱신된다

**출처**: 요청사항.md > 모니터링 항목 > 3. 디스크 사용량

### FR-004: 네트워크 트래픽 실시간 모니터링
**우선순위**: HIGH
**설명**: 네트워크 IN/OUT 트래픽을 실시간 차트로 표시한다. 수신(Bytes In)과 송신(Bytes Out)을 구분하여 시각화하며, 시간축 기반 트렌드를 제공한다.

**User Story**: 시스템 운영자로서, 나는 네트워크 수신/송신 트래픽을 실시간으로 보고 싶다, 네트워크 병목이나 이상 트래픽을 감지하기 위해.

**Acceptance Criteria**:
- [ ] 수신(Bytes In)과 송신(Bytes Out) 트래픽이 구분된 차트로 표시된다
- [ ] 실시간 시간축 기반 트렌드가 시각화된다
- [ ] 트래픽 단위(KB/s, MB/s)가 자동 변환되어 표시된다
- [ ] 3초 간격으로 자동 갱신된다

**출처**: 요청사항.md > 모니터링 항목 > 4. 네트워크 트래픽

### FR-005: 실시간 자동 갱신
**우선순위**: HIGH
**설명**: 모든 모니터링 데이터가 3초 간격으로 자동 갱신된다. 백엔드 API를 통해 시스템 정보를 수집하고 프론트엔드에 전달한다.

**User Story**: 시스템 운영자로서, 나는 수동 새로고침 없이 3초마다 자동으로 최신 데이터를 보고 싶다, 연속적인 모니터링이 가능하도록 하기 위해.

**Acceptance Criteria**:
- [ ] 페이지 로딩 후 3초 간격으로 모든 차트 데이터가 자동 갱신된다
- [ ] 백엔드 API가 시스템 정보를 수집하여 JSON으로 응답한다
- [ ] API 호출 실패 시 이전 데이터를 유지하고 재시도한다
- [ ] 갱신 주기가 UI에서 확인 가능하다 (마지막 업데이트 시간 표시)

**출처**: 요청사항.md > 기능 요구사항 > 실시간 업데이트

### FR-006: 다크 테마 대시보드 UI
**우선순위**: MEDIUM
**설명**: 다크 테마가 기본 적용된 깔끔하고 직관적인 대시보드 레이아웃을 제공한다. 반응형 그리드 구성으로 다양한 화면 크기에 대응한다.

**User Story**: 시스템 운영자로서, 나는 다크 테마의 반응형 대시보드를 사용하고 싶다, 장시간 모니터링 시 눈의 피로를 줄이고 다양한 기기에서 접근하기 위해.

**Acceptance Criteria**:
- [ ] 다크 테마가 기본으로 적용된다
- [ ] 4종 모니터링 차트가 그리드 레이아웃으로 배치된다
- [ ] 데스크톱(1920px), 태블릿(768px) 해상도에서 반응형으로 동작한다
- [ ] 차트 색상이 다크 배경에서 높은 가독성을 제공한다

**출처**: 요청사항.md > 기능 요구사항 > UI/UX

### FR-007: 시스템 정보 수집 백엔드 API
**우선순위**: HIGH
**설명**: Python psutil 라이브러리를 활용하여 CPU, 메모리, 디스크, 네트워크 정보를 수집하는 REST API를 제공한다.

**User Story**: 프론트엔드 대시보드로서, 나는 시스템 리소스 정보를 JSON API로 받고 싶다, 차트 데이터를 실시간으로 업데이트하기 위해.

**Acceptance Criteria**:
- [ ] GET /api/system/stats 엔드포인트가 전체 시스템 정보를 반환한다
- [ ] 응답에 CPU, 메모리, 디스크, 네트워크 데이터가 포함된다
- [ ] psutil 라이브러리로 정확한 시스템 정보를 수집한다
- [ ] 응답 시간이 500ms 이내이다
- [ ] CORS 설정으로 프론트엔드 도메인 접근을 허용한다

**출처**: 요청사항.md > 기술 스택 > Backend

## 3. 비기능 요구사항 (Non-Functional Requirements)

### NFR-001: 성능
**우선순위**: HIGH
**설명**: 대시보드 초기 로딩 시간 2초 이내, API 응답 시간 500ms 이내, 3초 갱신 주기 안정적 유지. 브라우저 메모리 사용량은 200MB 이하로 유지한다.

### NFR-002: 사용성
**우선순위**: HIGH
**설명**: 별도 교육 없이 사용 가능한 직관적 UI. 차트는 색상과 레이블로 데이터를 명확히 구분하며, 마우스 호버 시 상세 수치를 툴팁으로 제공한다.

### NFR-003: 호환성
**우선순위**: MEDIUM
**설명**: Chrome, Firefox, Safari, Edge 최신 2개 버전 지원. 데스크톱(1920x1080) 및 태블릿(768x1024) 해상도 지원.

### NFR-004: 유지보수성
**우선순위**: MEDIUM
**설명**: 모니터링 항목 추가 시 최소한의 코드 변경으로 확장 가능한 컴포넌트 구조. 차트 컴포넌트는 재사용 가능하게 설계한다.

## 4. 제약조건

### CON-001: 기술 스택
**설명**: 프론트엔드는 React + Recharts, 백엔드는 Python + psutil을 사용해야 한다.

### CON-002: 데이터 갱신 주기
**설명**: 시스템 정보 갱신 주기는 3초 간격으로 고정한다.

### CON-003: 단일 서버 모니터링
**설명**: 1차 버전은 대시보드가 실행되는 로컬 서버의 리소스만 모니터링한다.

### CON-004: 프로젝트 일정
**설명**: WBS 기준 분석 단계(2026-04-01 ~ 2026-04-23), 설계 단계(2026-04-24 ~ 2026-05-07) 내 완료해야 한다.
