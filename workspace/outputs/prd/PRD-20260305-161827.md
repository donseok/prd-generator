# 시스템 모니터링 웹 대시보드 PRD (Product Requirements Document)

**버전**: 1.0
**작성일**: 2026-03-05
**상태**: Draft

---

## 1. 개요

### 1.1 배경
현대 IT 운영 환경에서 서버 및 시스템 리소스의 실시간 모니터링은 안정적인 서비스 운영의 핵심 요소이다. 시스템 장애를 사전에 감지하고 리소스 병목 현상을 파악하기 위해서는 CPU, 메모리, 디스크, 네트워크 등 주요 지표를 실시간으로 시각화하는 도구가 필요하다.

기존에는 터미널 기반 도구(top, htop 등)나 복잡한 설정이 필요한 엔터프라이즈 모니터링 솔루션을 사용해왔으나, 직관적이고 접근성 높은 웹 기반 대시보드에 대한 수요가 증가하고 있다. 본 프로젝트는 경량화된 웹 대시보드를 개발하여 시스템 관리자와 개발자가 브라우저만으로 시스템 상태를 한눈에 파악할 수 있도록 한다.

### 1.2 목표
- 4가지 핵심 시스템 리소스(CPU, 메모리, 디스크, 네트워크)를 실시간으로 모니터링하는 웹 대시보드 구축
- 3초 간격의 실시간 데이터 갱신으로 시스템 상태의 즉각적 파악 지원
- 다크 테마 기반의 직관적이고 반응형 UI 제공

### 1.3 범위
#### 포함 범위
- CPU 사용률 실시간 라인 차트
- 메모리 사용률 실시간 라인 차트
- 디스크 사용량 파이 차트 (드라이브별)
- 네트워크 IN/OUT 트래픽 실시간 차트
- 3초 간격 자동 갱신
- 다크 테마 UI
- 반응형 대시보드 그리드 레이아웃
- Python 백엔드 API (psutil 기반)
- React 프론트엔드 (Recharts 기반)

#### 범위 외
- 사용자 인증 및 권한 관리
- 다중 서버 모니터링 (원격 서버)
- 알림/경고 시스템 (이메일, Slack 등)
- 히스토리 데이터 저장 및 조회
- 프로세스별 상세 모니터링
- 로그 수집 및 분석

### 1.4 대상 사용자
| 사용자 유형 | 역할 및 주요 활동 |
|------------|------------------|
| 시스템 관리자 | 서버 리소스 상태를 실시간으로 모니터링하고 이상 징후를 감지 |
| 개발자 | 개발/테스트 환경의 리소스 사용 현황을 파악하여 성능 최적화에 활용 |
| DevOps 엔지니어 | 배포 전후 시스템 리소스 변화를 모니터링하여 안정성 확인 |

### 1.5 성공 지표
- 대시보드 페이지 로딩 시간 2초 이내
- 데이터 갱신 주기 3초 이내 달성률 99% 이상
- 차트 렌더링 지연 500ms 이내
- 시스템 리소스(CPU, 메모리, 디스크, 네트워크) 4개 항목 모두 시각화 완료

## 2. 기능 요구사항 (Functional Requirements)

### FR-001: CPU 사용률 실시간 모니터링
**우선순위**: HIGH
**설명**: CPU 사용률(%)을 실시간 라인 차트로 표시한다. 시간축 기반으로 트렌드를 시각화하여 사용자가 CPU 부하 변화를 직관적으로 파악할 수 있도록 한다.

**User Story**: 시스템 관리자로서, 나는 CPU 사용률을 실시간 라인 차트로 확인하고 싶다, 시스템 부하 추이를 빠르게 파악하기 위해서.

**Acceptance Criteria**:
- [ ] CPU 사용률(%)이 라인 차트로 표시된다
- [ ] 시간축(X축) 기반으로 트렌드가 시각화된다
- [ ] 3초 간격으로 새로운 데이터 포인트가 추가된다
- [ ] 차트에 현재 CPU 사용률 수치가 표시된다

**출처**: 요청사항.md - "1. CPU 사용량" 섹션

---

### FR-002: 메모리 사용률 실시간 모니터링
**우선순위**: HIGH
**설명**: 메모리 사용률(%)을 실시간 라인 차트로 표시한다. 전체 메모리 대비 현재 사용량을 함께 표시하여 메모리 상태를 명확하게 전달한다.

**User Story**: 시스템 관리자로서, 나는 메모리 사용률과 전체 대비 사용량을 실시간으로 확인하고 싶다, 메모리 부족 상황을 사전에 감지하기 위해서.

**Acceptance Criteria**:
- [ ] 메모리 사용률(%)이 라인 차트로 표시된다
- [ ] 전체 메모리 용량 대비 현재 사용량이 표시된다
- [ ] 3초 간격으로 데이터가 갱신된다
- [ ] 사용 중/가용 메모리 수치가 표시된다

**출처**: 요청사항.md - "2. 메모리 사용량" 섹션

---

### FR-003: 디스크 사용량 시각화
**우선순위**: HIGH
**설명**: 디스크 사용량과 잔여 공간을 파이 차트로 시각화한다. 시스템에 연결된 각 드라이브별로 사용량을 구분하여 표시한다.

**User Story**: 시스템 관리자로서, 나는 각 드라이브의 디스크 사용/잔여 공간을 파이 차트로 확인하고 싶다, 디스크 공간 부족을 예방하기 위해서.

**Acceptance Criteria**:
- [ ] 디스크 사용/잔여 공간이 파이 차트로 표시된다
- [ ] 각 드라이브(파티션)별 사용량이 구분 표시된다
- [ ] 사용량(GB/TB)과 비율(%)이 함께 표시된다
- [ ] 데이터가 주기적으로 갱신된다

**출처**: 요청사항.md - "3. 디스크 사용량" 섹션

---

### FR-004: 네트워크 트래픽 실시간 모니터링
**우선순위**: HIGH
**설명**: 네트워크 IN/OUT 트래픽을 실시간 차트로 표시한다. 수신(Bytes In)과 송신(Bytes Out)을 구분하여 시각화하여 네트워크 활동을 모니터링할 수 있도록 한다.

**User Story**: 시스템 관리자로서, 나는 네트워크 수신/송신 트래픽을 실시간 차트로 확인하고 싶다, 비정상적인 네트워크 활동을 감지하기 위해서.

**Acceptance Criteria**:
- [ ] 네트워크 수신(Bytes In) 트래픽이 차트로 표시된다
- [ ] 네트워크 송신(Bytes Out) 트래픽이 차트로 표시된다
- [ ] IN/OUT이 시각적으로 구분된다 (색상 등)
- [ ] 3초 간격으로 데이터가 갱신된다

**출처**: 요청사항.md - "4. 네트워크 트래픽" 섹션

---

### FR-005: 실시간 데이터 자동 갱신
**우선순위**: HIGH
**설명**: 백엔드 API를 통해 3초 간격으로 시스템 정보를 자동 수집하고 프론트엔드에 전달한다. 사용자 개입 없이 대시보드가 자동으로 최신 데이터를 표시한다.

**User Story**: 사용자로서, 나는 별도 조작 없이 대시보드가 자동으로 갱신되기를 원한다, 항상 최신 시스템 상태를 확인하기 위해서.

**Acceptance Criteria**:
- [ ] 3초 간격으로 백엔드 API가 호출된다
- [ ] API 응답 데이터가 차트에 자동 반영된다
- [ ] 갱신 중에도 UI가 끊김 없이 동작한다
- [ ] API 호출 실패 시 이전 데이터가 유지된다

**출처**: 요청사항.md - "실시간 업데이트" 섹션

---

### FR-006: 백엔드 시스템 정보 수집 API
**우선순위**: HIGH
**설명**: Python과 psutil 라이브러리를 활용하여 시스템 리소스 정보(CPU, 메모리, 디스크, 네트워크)를 수집하고 REST API로 제공한다.

**User Story**: 프론트엔드 개발자로서, 나는 표준화된 API를 통해 시스템 정보를 받고 싶다, 차트 데이터를 안정적으로 렌더링하기 위해서.

**Acceptance Criteria**:
- [ ] GET 엔드포인트로 CPU 사용률을 조회할 수 있다
- [ ] GET 엔드포인트로 메모리 사용률 및 전체 용량을 조회할 수 있다
- [ ] GET 엔드포인트로 디스크 사용량(드라이브별)을 조회할 수 있다
- [ ] GET 엔드포인트로 네트워크 트래픽(IN/OUT)을 조회할 수 있다
- [ ] 응답 형식은 JSON이다

**출처**: 요청사항.md - "기술 스택" 및 "실시간 업데이트" 섹션

---

### FR-007: 다크 테마 UI
**우선순위**: MEDIUM
**설명**: 대시보드 전체에 다크 테마를 적용한다. 어두운 배경에 밝은 텍스트와 차트 색상을 사용하여 장시간 모니터링 시 눈의 피로를 줄인다.

**User Story**: 사용자로서, 나는 다크 테마가 적용된 대시보드를 사용하고 싶다, 장시간 모니터링 시 눈의 피로를 줄이기 위해서.

**Acceptance Criteria**:
- [ ] 대시보드 배경이 어두운 색상으로 표시된다
- [ ] 텍스트와 차트 요소가 다크 배경에서 명확하게 보인다
- [ ] 차트 색상이 다크 테마에 맞게 최적화되어 있다

**출처**: 요청사항.md - "UI/UX" 섹션

---

### FR-008: 반응형 대시보드 레이아웃
**우선순위**: MEDIUM
**설명**: 대시보드를 그리드 기반 반응형 레이아웃으로 구성한다. 다양한 화면 크기에서 차트들이 적절하게 배치되어 가독성을 유지한다.

**User Story**: 사용자로서, 나는 다양한 화면 크기에서 대시보드가 잘 표시되기를 원한다, 데스크톱과 태블릿에서 모두 활용하기 위해서.

**Acceptance Criteria**:
- [ ] 4개 차트가 그리드 형태로 배치된다
- [ ] 브라우저 창 크기 변경 시 레이아웃이 자동 조정된다
- [ ] 최소 1024px 너비에서 모든 차트가 정상 표시된다
- [ ] 각 차트 영역이 깔끔하게 구분된다

**출처**: 요청사항.md - "UI/UX" 섹션

## 3. 비기능 요구사항 (Non-Functional Requirements)

### NFR-001: 성능 - 데이터 갱신 주기
**우선순위**: HIGH
**설명**: 시스템 정보 데이터는 3초 이내 간격으로 갱신되어야 한다. API 응답 시간은 1초 이내여야 한다.

### NFR-002: 성능 - 페이지 로딩
**우선순위**: HIGH
**설명**: 대시보드 초기 페이지 로딩 시간은 2초 이내여야 한다. 차트 렌더링 지연은 500ms 이내여야 한다.

### NFR-003: 사용성 - 직관적 인터페이스
**우선순위**: MEDIUM
**설명**: 별도 교육 없이 대시보드의 정보를 즉시 이해할 수 있어야 한다. 차트 레이블, 단위, 범례가 명확히 표시되어야 한다.

### NFR-004: 호환성 - 브라우저 지원
**우선순위**: MEDIUM
**설명**: Chrome, Firefox, Edge 등 주요 모던 브라우저에서 정상 동작해야 한다.

### NFR-005: 안정성 - 연속 운영
**우선순위**: MEDIUM
**설명**: 대시보드가 장시간(24시간 이상) 열려 있어도 메모리 누수 없이 안정적으로 동작해야 한다.

## 4. 제약조건

### CON-001: 프론트엔드 기술 스택
**설명**: 프론트엔드는 React와 Recharts 라이브러리를 사용하여 개발해야 한다.

### CON-002: 백엔드 기술 스택
**설명**: 백엔드는 Python과 psutil 라이브러리를 사용하여 시스템 정보를 수집해야 한다.

### CON-003: 로컬 서버 모니터링
**설명**: 본 시스템은 대시보드가 실행되는 로컬 서버의 리소스만 모니터링한다. 원격 서버 모니터링은 범위 외이다.

## 5. 마일스톤

### M1: 백엔드 API 개발 - 1주
**목표**: 시스템 리소스 수집 API 완성
**주요 산출물**:
- Python 백엔드 서버 설정
- psutil 기반 시스템 정보 수집 모듈
- REST API 엔드포인트 (CPU, 메모리, 디스크, 네트워크)
- API 테스트

### M2: 프론트엔드 대시보드 개발 - 1.5주
**목표**: 4개 차트가 포함된 대시보드 UI 완성
**주요 산출물**:
- React 프로젝트 구조 설정
- CPU 사용률 라인 차트 컴포넌트
- 메모리 사용률 라인 차트 컴포넌트
- 디스크 사용량 파이 차트 컴포넌트
- 네트워크 트래픽 차트 컴포넌트
- 다크 테마 적용
- 반응형 그리드 레이아웃

### M3: 통합 및 테스트 - 0.5주
**목표**: 프론트엔드-백엔드 통합 및 실시간 데이터 갱신 검증
**주요 산출물**:
- 프론트엔드-백엔드 API 연동
- 3초 간격 자동 갱신 구현
- 통합 테스트
- 버그 수정 및 최적화
