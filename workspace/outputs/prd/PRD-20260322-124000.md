# 시스템 모니터링 웹 대시보드 PRD (Product Requirements Document)

**버전**: 1.0
**작성일**: 2026-03-22
**상태**: Draft

---

## 1. 개요

### 1.1 배경
현대 IT 인프라 운영에서 서버 및 시스템 리소스의 실시간 모니터링은 안정적인 서비스 운영의 핵심 요소이다. 기존에는 CLI 기반 도구(top, htop, vmstat 등)를 통해 시스템 상태를 확인했으나, 직관적인 시각화 부재로 인해 이상 징후를 빠르게 파악하기 어려운 한계가 있었다.

이에 따라 CPU, 메모리, 디스크, 네트워크 트래픽 등 주요 시스템 리소스를 웹 기반 대시보드로 실시간 시각화하여, 운영자가 별도의 터미널 접속 없이도 시스템 상태를 한눈에 파악하고 신속하게 대응할 수 있는 모니터링 도구를 개발한다.

### 1.2 목표
- 4가지 핵심 시스템 리소스(CPU, 메모리, 디스크, 네트워크)를 실시간으로 모니터링할 수 있는 웹 대시보드를 제공한다
- 3초 간격의 자동 갱신을 통해 준 실시간(Near Real-Time) 모니터링 환경을 구현한다
- 다크 테마 기반의 직관적이고 깔끔한 UI/UX를 제공한다
- 반응형 레이아웃으로 다양한 화면 크기에서 최적의 사용 경험을 보장한다

### 1.3 범위
#### 포함 범위
- CPU 사용률 실시간 라인 차트
- 메모리 사용률 실시간 라인 차트
- 디스크 사용량 파이 차트 (드라이브별)
- 네트워크 IN/OUT 트래픽 실시간 차트
- 3초 주기 자동 데이터 갱신
- 다크 테마 UI
- 반응형 대시보드 그리드 레이아웃
- 백엔드 API (시스템 정보 수집 및 전달)

#### 범위 외
- 알림/경고 시스템 (이메일, SMS, Slack 등)
- 히스토리 데이터 저장 및 조회
- 다중 서버 모니터링 (리모트 에이전트)
- 사용자 인증 및 권한 관리
- 로그 수집 및 분석
- 프로세스별 상세 리소스 추적

### 1.4 대상 사용자
| 사용자 유형 | 역할 및 주요 활동 |
|------------|------------------|
| 시스템 관리자 | 서버 리소스 상태를 실시간으로 모니터링하고 이상 징후 발생 시 즉각 대응 |
| DevOps 엔지니어 | 배포 전후 시스템 리소스 변화를 확인하고 성능 영향을 분석 |
| 개발자 | 개발/테스트 환경의 리소스 사용 현황을 확인하여 성능 병목 파악 |

### 1.5 성공 지표
- 대시보드 초기 로딩 시간 3초 이내
- 데이터 갱신 지연(API 호출~화면 반영) 500ms 이내
- 차트 렌더링 시 프레임 드롭 없이 60fps 유지
- 브라우저 메모리 사용량 200MB 이하 (1시간 연속 구동 기준)

## 2. 기능 요구사항 (Functional Requirements)

### FR-001: CPU 사용률 실시간 모니터링
**우선순위**: HIGH
**설명**: 시스템의 CPU 사용률(%)을 실시간 라인 차트로 시각화한다. 시간축(X축)을 기반으로 CPU 사용률의 변화 트렌드를 확인할 수 있어야 한다.

**User Story**: 시스템 관리자로서, 나는 CPU 사용률 변화를 실시간 라인 차트로 확인하고 싶다, 비정상적인 CPU 급증을 빠르게 감지하기 위해.

**Acceptance Criteria**:
- [ ] CPU 사용률(%)이 실시간 라인 차트로 표시된다
- [ ] X축은 시간, Y축은 0~100% 범위로 표시된다
- [ ] 최근 N분간의 데이터가 시간축에 연속적으로 표시된다
- [ ] 차트 업데이트 시 부드러운 애니메이션이 적용된다

**출처**: 요청사항.md > 모니터링 항목 > 1. CPU 사용량

---

### FR-002: 메모리 사용률 실시간 모니터링
**우선순위**: HIGH
**설명**: 시스템의 메모리 사용률(%)을 실시간 라인 차트로 시각화한다. 전체 메모리 대비 현재 사용량을 표시하여 메모리 부족 상황을 조기에 파악할 수 있어야 한다.

**User Story**: 시스템 관리자로서, 나는 메모리 사용률과 전체 메모리 대비 사용량을 실시간으로 확인하고 싶다, 메모리 부족으로 인한 서비스 장애를 예방하기 위해.

**Acceptance Criteria**:
- [ ] 메모리 사용률(%)이 실시간 라인 차트로 표시된다
- [ ] 전체 메모리 용량(GB) 대비 사용량(GB)이 수치로 표시된다
- [ ] X축은 시간, Y축은 0~100% 범위로 표시된다
- [ ] 차트 업데이트 시 부드러운 애니메이션이 적용된다

**출처**: 요청사항.md > 모니터링 항목 > 2. 메모리 사용량

---

### FR-003: 디스크 사용량 시각화
**우선순위**: HIGH
**설명**: 각 드라이브(파티션)별 디스크 사용량과 잔여 공간을 파이 차트로 시각화한다.

**User Story**: 시스템 관리자로서, 나는 각 드라이브의 디스크 사용/잔여 공간을 파이 차트로 한눈에 확인하고 싶다, 디스크 용량 부족을 사전에 파악하기 위해.

**Acceptance Criteria**:
- [ ] 각 드라이브(파티션)별 파이 차트가 표시된다
- [ ] 사용 중 공간과 잔여 공간이 구분되어 시각화된다
- [ ] 사용량(GB)과 사용률(%)이 수치로 표시된다
- [ ] 마운트 포인트(드라이브 문자)가 레이블로 표시된다

**출처**: 요청사항.md > 모니터링 항목 > 3. 디스크 사용량

---

### FR-004: 네트워크 트래픽 실시간 모니터링
**우선순위**: HIGH
**설명**: 네트워크 IN(수신)/OUT(송신) 트래픽을 실시간 차트로 시각화한다. 수신과 송신 데이터를 구분하여 네트워크 부하 상태를 모니터링할 수 있어야 한다.

**User Story**: DevOps 엔지니어로서, 나는 네트워크 수신/송신 트래픽을 실시간 차트로 구분하여 확인하고 싶다, 네트워크 병목이나 비정상 트래픽을 신속히 감지하기 위해.

**Acceptance Criteria**:
- [ ] 수신(Bytes In)과 송신(Bytes Out) 트래픽이 구분된 라인 차트로 표시된다
- [ ] X축은 시간, Y축은 트래픽 양(자동 단위 변환: B, KB, MB)으로 표시된다
- [ ] IN/OUT 라인이 서로 다른 색상으로 구분된다
- [ ] 차트 업데이트 시 부드러운 애니메이션이 적용된다

**출처**: 요청사항.md > 모니터링 항목 > 4. 네트워크 트래픽

---

### FR-005: 실시간 자동 데이터 갱신
**우선순위**: HIGH
**설명**: 백엔드 API를 통해 3초 간격으로 시스템 정보를 자동 수집하여 대시보드 차트를 갱신한다.

**User Story**: 시스템 관리자로서, 나는 대시보드가 3초마다 자동으로 최신 데이터를 표시하길 원한다, 수동 새로고침 없이 항상 최신 상태를 확인하기 위해.

**Acceptance Criteria**:
- [ ] 3초 간격으로 백엔드 API를 호출하여 최신 시스템 정보를 가져온다
- [ ] API 응답 데이터가 모든 차트에 동시에 반영된다
- [ ] API 호출 실패 시 이전 데이터를 유지하고 재시도한다
- [ ] 페이지 로드 시 즉시 첫 번째 데이터를 가져온다

**출처**: 요청사항.md > 기능 요구사항 > 실시간 업데이트

---

### FR-006: 다크 테마 UI
**우선순위**: MEDIUM
**설명**: 전체 대시보드에 다크 테마를 적용하여 장시간 모니터링 시 눈의 피로를 줄이고, 차트 데이터의 가독성을 높인다.

**User Story**: 시스템 관리자로서, 나는 다크 테마 기반의 대시보드를 사용하고 싶다, 장시간 모니터링 시 눈의 피로를 줄이기 위해.

**Acceptance Criteria**:
- [ ] 전체 UI가 다크 배경(어두운 색상 계열)으로 구성된다
- [ ] 차트 색상이 다크 배경에서 높은 대비로 가독성이 확보된다
- [ ] 텍스트, 아이콘 등 UI 요소가 다크 테마에 맞게 표시된다

**출처**: 요청사항.md > 기능 요구사항 > UI/UX

---

### FR-007: 반응형 대시보드 레이아웃
**우선순위**: MEDIUM
**설명**: 4개의 모니터링 차트를 그리드 형태로 배치하며, 다양한 화면 크기(데스크톱, 태블릿)에서 자동으로 레이아웃을 조정한다.

**User Story**: 개발자로서, 나는 다양한 화면 크기에서 대시보드를 볼 수 있길 원한다, 여러 디바이스에서 편리하게 모니터링하기 위해.

**Acceptance Criteria**:
- [ ] 데스크톱(1200px+)에서 2x2 그리드로 4개 차트가 배치된다
- [ ] 태블릿(768~1199px)에서 1x4 또는 2x2 그리드로 재배치된다
- [ ] 각 차트가 컨테이너 크기에 맞게 자동 리사이즈된다
- [ ] 깔끔하고 직관적인 레이아웃이 유지된다

**출처**: 요청사항.md > 기능 요구사항 > UI/UX

---

### FR-008: 시스템 정보 수집 백엔드 API
**우선순위**: HIGH
**설명**: Python psutil 라이브러리를 활용하여 서버의 CPU, 메모리, 디스크, 네트워크 정보를 수집하고 REST API로 제공한다.

**User Story**: 프론트엔드 대시보드로서, 나는 백엔드 API로부터 JSON 형태의 시스템 정보를 받고 싶다, 차트 데이터를 갱신하기 위해.

**Acceptance Criteria**:
- [ ] GET API 엔드포인트로 CPU, 메모리, 디스크, 네트워크 정보를 JSON으로 반환한다
- [ ] CPU: 사용률(%) 반환
- [ ] 메모리: 사용률(%), 전체 용량, 사용 중 용량 반환
- [ ] 디스크: 드라이브별 전체/사용/잔여 용량 반환
- [ ] 네트워크: 수신/송신 바이트 수 반환
- [ ] API 응답 시간이 200ms 이내이다

**출처**: 요청사항.md > 기술 스택 > Backend, 기능 요구사항 > 실시간 업데이트

## 3. 비기능 요구사항 (Non-Functional Requirements)

### NFR-001: 성능
**우선순위**: HIGH
**설명**: 대시보드 초기 로딩 3초 이내, API 응답 200ms 이내, 차트 렌더링 60fps 유지. 1시간 연속 구동 시 브라우저 메모리 200MB 이하.

### NFR-002: 호환성
**우선순위**: MEDIUM
**설명**: Chrome, Firefox, Edge 최신 버전에서 정상 동작해야 한다. Windows, macOS, Linux 환경의 시스템 정보를 수집할 수 있어야 한다.

### NFR-003: 가용성
**우선순위**: MEDIUM
**설명**: 백엔드 API 장애 시에도 프론트엔드가 마지막 수신 데이터를 유지하여 표시해야 한다. API 재접속 시 자동으로 데이터 갱신이 복구되어야 한다.

### NFR-004: 사용성
**우선순위**: MEDIUM
**설명**: 별도의 매뉴얼 없이 대시보드를 이해하고 사용할 수 있어야 한다. 차트 레이블, 단위, 범례가 명확하게 표시되어야 한다.

## 4. 제약조건

### CON-001: 프론트엔드 기술 스택
**설명**: 프론트엔드는 React와 Recharts 라이브러리를 사용하여 개발한다.

### CON-002: 백엔드 기술 스택
**설명**: 백엔드는 Python과 psutil 라이브러리를 사용하여 시스템 정보를 수집한다.

### CON-003: 단일 서버 모니터링
**설명**: 이번 버전에서는 백엔드가 실행 중인 로컬 서버의 리소스만 모니터링한다. 원격 서버 모니터링은 지원하지 않는다.

### CON-004: 데이터 비영속성
**설명**: 수집된 모니터링 데이터는 메모리에만 유지하며, 서버 재시작 시 이전 데이터는 유실된다. 영구 저장은 범위 외이다.

## 5. 마일스톤

### M1: 백엔드 API 개발 - 1~2주
**목표**: 시스템 리소스 수집 API 구현 및 테스트
**주요 산출물**:
- Python 백엔드 서버 (FastAPI/Flask)
- 시스템 정보 수집 API 엔드포인트
- API 응답 JSON 스키마 정의

### M2: 프론트엔드 대시보드 개발 - 2~3주
**목표**: React 기반 대시보드 UI 및 차트 구현
**주요 산출물**:
- 다크 테마 대시보드 레이아웃
- 4개 모니터링 차트 컴포넌트 (CPU, 메모리, 디스크, 네트워크)
- 실시간 데이터 갱신 로직 (3초 주기 폴링)
- 반응형 그리드 레이아웃

### M3: 통합 테스트 및 최적화 - 1주
**목표**: 프론트엔드-백엔드 통합 및 성능 최적화
**주요 산출물**:
- 통합 테스트 완료
- 성능 최적화 (메모리 누수 방지, 차트 렌더링 최적화)
- 배포 가이드 문서
