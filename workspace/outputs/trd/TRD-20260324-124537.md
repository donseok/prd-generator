## 1. 기술 요약 (Executive Summary)

본 프로젝트는 단일 서버의 CPU, 메모리, 디스크, 네트워크 리소스를 실시간으로 시각화하는 웹 대시보드이다. 프론트엔드는 PRD에서 지정한 React + Recharts 조합을 사용하며, 3초 간격 폴링 방식으로 백엔드 API에서 시스템 데이터를 수집한다.

백엔드는 Python FastAPI 프레임워크 위에 psutil 라이브러리를 활용하여 시스템 리소스 정보를 수집하고 REST API로 제공한다. FastAPI의 비동기 처리 능력으로 다수의 동시 폴링 요청을 효율적으로 처리하며, 자동 생성되는 OpenAPI 문서로 API 명세를 관리한다.

아키텍처는 프론트엔드-백엔드 2-Tier 모놀리식 구조를 채택한다. 단일 서버 모니터링이라는 범위를 고려할 때, 마이크로서비스나 메시지 큐 등의 복잡한 인프라 없이 간결하고 유지보수가 용이한 구조가 적합하다. 별도의 데이터베이스 없이 인메모리 링 버퍼로 최근 5분간의 시계열 데이터를 유지하여, 시스템 복잡도를 최소화한다.

### 3.2 계층별 설명
| 계층 | 설명 | 핵심 컴포넌트 |
|------|------|-------------|
| Presentation | React SPA, 차트 시각화, 다크 테마 UI | Dashboard, CpuChart, MemoryChart, DiskChart, NetworkChart |
| API Gateway | 리버스 프록시, 정적 파일 서빙 | Nginx |
| Application | REST API, 시스템 데이터 수집/가공 | FastAPI, SystemCollector, RingBuffer |
| System | OS 리소스 정보 제공 | psutil |

### 3.3 데이터 흐름
1. **수집**: `SystemCollector`가 psutil을 통해 OS로부터 CPU/메모리/디스크/네트워크 정보 수집
2. **저장**: `RingBuffer`에 타임스탬프와 함께 인메모리 저장 (최근 100개 포인트, 약 5분)
3. **제공**: FastAPI 엔드포인트가 RingBuffer의 현재 스냅샷 + 히스토리를 JSON으로 응답
4. **표시**: React 프론트엔드가 3초 간격으로 API 폴링, Recharts로 차트 렌더링

## 4. 데이터베이스 설계 (Database Design)

### 4.1 데이터베이스 유형 및 엔진
- **유형**: 인메모리 (별도 DB 불필요)
- **구현**: Python `collections.deque` 기반 Ring Buffer
- **사유**: PRD 범위가 실시간 모니터링에 한정되며, 히스토리 저장이 범위 외로 명시됨. 인메모리 구조로 지연 시간 최소화.

### 4.2 데이터 구조

```
SystemSnapshot {
    timestamp: datetime      # 수집 시각 (ISO 8601)
    cpu: CpuData            # CPU 정보
    memory: MemoryData      # 메모리 정보
    disk: DiskData[]        # 디스크 정보 (파티션별)
    network: NetworkData    # 네트워크 정보
}

CpuData {
    usage_percent: float    # CPU 사용률 (0.0 ~ 100.0)
    core_count: int         # CPU 코어 수
}

MemoryData {
    usage_percent: float    # 메모리 사용률 (0.0 ~ 100.0)
    total_gb: float         # 전체 메모리 (GB)
    used_gb: float          # 사용 중 메모리 (GB)
    available_gb: float     # 가용 메모리 (GB)
}

DiskData {
    device: string          # 드라이브명 (예: /dev/sda1, C:\)
    mountpoint: string      # 마운트 포인트
    total_gb: float         # 전체 용량 (GB)
    used_gb: float          # 사용 용량 (GB)
    free_gb: float          # 잔여 용량 (GB)
    usage_percent: float    # 사용률 (%)
}

NetworkData {
    bytes_sent: int         # 누적 송신 바이트
    bytes_recv: int         # 누적 수신 바이트
    bytes_sent_per_sec: float  # 초당 송신 바이트
    bytes_recv_per_sec: float  # 초당 수신 바이트
}
```

### 4.3 Ring Buffer 사양
| 항목 | 값 | 설명 |
|------|-----|------|
| 최대 크기 | 100 entries | 3초 × 100 = 약 5분 |
| 데이터 포인트 크기 | ~500 bytes | JSON 직렬화 기준 |
| 메모리 사용량 | ~50 KB | 100 × 500 bytes |
| 오버플로우 정책 | FIFO | 가장 오래된 데이터 자동 삭제 |

## 5. API 명세 (API Specification)

### 5.1 공통 사항
- **Base URL**: `/api/v1`
- **인증 방식**: 없음 (PRD에서 인증이 범위 외로 명시)
- **공통 헤더**: `Content-Type: application/json`
- **에러 처리**: `{ "error": { "code": "ERROR_CODE", "message": "설명" } }`

### 5.2 엔드포인트 목록

| Method | Path | 설명 | 인증 | 관련 FR |
|--------|------|------|------|---------|

## 9. 기술 리스크 (Technical Risks)

| ID | 리스크 | 영향도 | 대응 방안 | 대안 (Contingency) |
|----|--------|--------|----------|-------------------|
| TR-001 | psutil이 특정 OS에서 권한 부족으로 일부 데이터 수집 실패 | MEDIUM | 권한 체크 후 graceful fallback (N/A 표시) | Docker privileged 모드 또는 sudo 실행 |
| TR-002 | 3초 폴링으로 인한 브라우저 메모리 누수 (장시간 운영 시) | MEDIUM | Ring Buffer 패턴으로 DOM 노드 수 제한, useEffect cleanup | Web Worker로 데이터 처리 분리 |
| TR-003 | Recharts 대량 데이터 포인트 렌더링 성능 저하 | LOW | 100개 포인트 제한 + SVG 최적화 | Canvas 기반 차트 라이브러리(Chart.js)로 교체 |
| TR-004 | 네트워크 트래픽 계산 시 psutil counter overflow | LOW | delta 계산 시 overflow 감지 로직 추가 | 주기적 카운터 리셋 |
| TR-005 | 다중 디스크 파티션 시 파이 차트 가독성 저하 | LOW | 5개 이상 파티션 시 상위 5개만 표시 + "기타" 그룹핑 | 테이블 뷰 대체 옵션 |
