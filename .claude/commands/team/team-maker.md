# 에이전트 팀 구성 문서 생성

> **중요**: 이 작업을 시작하기 전에 이전 컨텍스트를 클리어하고 새로운 세션으로 시작합니다.

당신은 소프트웨어 프로젝트의 에이전트 팀을 설계하는 전문가입니다.
최신 PRD, TRD, WBS 문서를 기반으로 프로젝트 수행에 최적화된 에이전트 팀 구성 문서를 생성하세요.

---

## 1단계: 문서 파일 읽기

다음 폴더에서 가장 최신 JSON 파일을 각각 읽으세요:

1. **PRD** (필수): `workspace/outputs/prd/PRD-*.json`
2. **TRD** (권장): `workspace/outputs/trd/TRD-*.json`
3. **WBS** (권장): `workspace/outputs/wbs/WBS-*.json`

- 파일명의 타임스탬프(YYYYMMDD-HHMMSS) 기준으로 최신 파일 판별
- PRD가 없으면 에러 메시지 출력 후 중단
- TRD/WBS가 없으면 PRD 기반으로만 생성 (경고 표시)

각 문서에서 다음 정보를 추출하세요:

### PRD에서 추출
- 프로젝트명, 개요, 목표
- 기능 요구사항 (FR) 목록 및 우선순위
- 비기능 요구사항 (NFR)
- 제약조건

### TRD에서 추출
- 기술 스택 (카테고리별)
- 시스템 아키텍처 스타일 및 레이어
- 데이터베이스 설계 (엔티티 수, DB 엔진)
- API 엔드포인트 수
- 보안 요구사항
- 기술 리스크

### WBS에서 추출
- 총 공수 (시간, M/M)
- 페이즈 목록 및 태스크 수
- 역할별 공수 배분
- 크리티컬 패스
- 팀 규모, 방법론, 스프린트 기간

---

## 2단계: 에이전트 팀 설계

추출한 정보를 기반으로 최적의 에이전트 팀을 설계합니다:

### 설계 원칙
1. **역할 매칭**: WBS의 역할별 공수 배분에 비례하여 에이전트 역할 결정
2. **기술 커버리지**: TRD의 모든 기술 스택을 팀이 커버할 수 있도록 구성
3. **작업 커버리지**: WBS의 모든 페이즈와 태스크를 팀이 커버
4. **리드 배정**: 가장 공수가 큰 역할에 리드급 에이전트 배치
5. **교차 역할**: 에이전트 간 일부 역할 중복으로 유연성 확보

### 팀 규모 기본값
- WBS의 team_size가 있으면 해당 값 사용
- 없으면 기본 5명

---

## 4단계: 파일 저장

생성한 문서를 다음 위치에 저장하세요:

**Markdown 파일**: `workspace/outputs/agent-team/TEAM-[YYYYMMDD-HHMMSS].md`

---

## 작성 지침

1. **실용성**: 각 에이전트의 시스템 프롬프트는 Claude Code에서 바로 사용 가능한 수준으로 상세하게
2. **구체성**: 추상적인 역할이 아닌, 프로젝트의 실제 기술 스택과 태스크에 기반한 구체적 역할
3. **균형**: 공수 배분에 기반한 합리적인 업무 분배
4. **협업**: 에이전트 간 명확한 인터페이스와 협업 구조 정의
5. **한국어**: 모든 내용을 한국어로 작성

---

## 에러 처리

- **PRD 없음**: "workspace/outputs/prd/ 폴더에 PRD 파일이 없습니다. /prd:prd-maker를 먼저 실행하세요." 표시 후 중단
- **TRD 없음**: 경고 표시 후 PRD 기반으로만 기술 스택 추론
- **WBS 없음**: 경고 표시 후 기본 역할 배분으로 생성
