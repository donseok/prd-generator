## 1. 시스템 아키텍처

### 1.1 전체 구성

```
┌─────────────────┐     ┌──────────────────┐     ┌─────────────────┐
│  Next.js 14     │────▶│  FastAPI          │────▶│  Claude CLI     │
│  (Port 3000)    │     │  (Port 8000)      │     │  (AI Engine)    │
│  Frontend       │     │  Backend          │     │  subprocess     │
└─────────────────┘     └──────────────────┘     └─────────────────┘
                               │
                        ┌──────┴──────┐
                        │  File Store │
                        │  /data/     │
                        │  /workspace/│
                        └─────────────┘
```

### 1.2 7-Layer 처리 파이프라인

```
입력 → [L1: Parsing] → [L2: Normalization] → [L3: Validation] → [L4: Generation] → PRD
                                                    ↓                                ↓
                                              PM_REVIEW (< 0.8)              ┌───────┴───────┐
                                                                             ↓               ↓
                                                                      [L5: Proposal]  [L6: TRD]
                                                                             ↓               ↓
                                                                          제안서        [L7: WBS]
```

- **Layer 1** (`app/layers/layer1_parsing/`): ParserFactory가 파일 확장자에 따라 파서 자동 선택
- **Layer 2** (`app/layers/layer2_normalization/`): AI로 요구사항 추출, FR/NFR/Constraint 분류, User Story 생성
- **Layer 3** (`app/layers/layer3_validation/`): 완전성/일관성 검증, 신뢰도 < 0.8이면 PM 리뷰로 라우팅
- **Layer 4** (`app/layers/layer4_generation/`): PRDDocument 최종 생성
- **Layer 5** (`app/layers/layer5_proposal/`): PRD → ProposalDocument (스토리텔링 기반)
- **Layer 6** (`app/layers/layer6_trd/`): PRD → TRDDocument (아키텍처, API 명세)
- **Layer 7** (`app/layers/layer7_wbs/`): PRD + TRD → WBSDocument (작업 분해, 공수 산정)

### 1.3 핵심 서비스

| 서비스 | 파일 | 역할 |
|--------|------|------|
| Claude Client | `app/services/claude_client.py` | Claude CLI를 subprocess로 호출. 재시도 로직, ThreadPoolExecutor 비동기 처리 |
| Orchestrator | `app/services/orchestrator.py` | Layer 1~4 파이프라인 오케스트레이션 |
| Document Orchestrator | `app/services/document_orchestrator.py` | 전체 문서 파이프라인 (PRD→TRD→WBS→Proposal) |
| File Storage | `app/services/file_storage.py` | JSON 파일 기반 저장소 (`/data/`) |
| Cache | `app/services/cache.py` | 캐시 관리 |

### 1.4 처리 상태 흐름

```
PENDING → PARSING → NORMALIZING → VALIDATING → GENERATING → COMPLETED
                                       ↓
                                   PM_REVIEW → GENERATING → COMPLETED
```

## 2. 설치 및 환경 구성

### 2.1 사전 요구사항

- **Python 3.12+** (Windows)
- **Node.js 18+** (Next.js 프론트엔드용)
- **Claude CLI** (시스템 PATH에 등록)
- **Git**

### 2.2 백엔드 설치

```bash
cd D:\prd-generator

# Python 의존성 설치
pip install -r requirements.txt
```

주요 의존성:
- `fastapi`, `uvicorn` - 웹 서버
- `anthropic` - Claude API (참조용, 실제로는 CLI 사용)
- `python-pptx` - PPT 생성
- `python-docx` - DOCX 생성
- `openpyxl`, `pandas` - Excel 처리
- `Pillow` - 이미지 처리
- `lxml` - XML 파싱
- `mail-parser` - 이메일 파싱
- `PyPDF2` - PDF 처리

### 2.3 프론트엔드 설치

```bash
cd D:\prd-generator\frontend
npm install
```

주요 의존성:
- `next` 14 - React 프레임워크
- `@tanstack/react-query` - 서버 상태 관리
- `axios` - HTTP 클라이언트
- `react-dropzone` - 파일 업로드
- `react-markdown`, `remark-gfm` - 마크다운 렌더링
- `lucide-react` - 아이콘

### 2.4 환경 변수 설정

```bash
cp .env.example .env
```

`.env` 파일을 편집하여 필요한 값을 설정합니다 (5장 참조).

## 5. 환경 변수 설정

`.env` 파일의 주요 설정:

| 변수 | 기본값 | 설명 |
|------|--------|------|
| `HOST` | `0.0.0.0` | 서버 바인딩 주소 |
| `PORT` | `8000` | 서버 포트 |
| `AUTO_APPROVE_THRESHOLD` | `0.8` | PM 리뷰 없이 자동 승인하는 신뢰도 임계값 (0.0~1.0) |
| `NEXT_PUBLIC_API_URL` | `http://localhost:8000/api/v1` | 프론트엔드에서 사용하는 API URL |

### 신뢰도 임계값 조정

- **0.9**: 엄격한 검증. 대부분의 요구사항이 PM 리뷰를 거침
- **0.8** (기본): 균형잡힌 설정. 애매한 항목만 리뷰
- **0.6**: 느슨한 검증. 명확히 문제있는 항목만 리뷰
- **0.0**: 모든 요구사항 자동 승인 (리뷰 비활성화)

## 8. CLI 스크립트 관리

### 8.1 스크립트 목록

| 스크립트 | 명령어 | 입력 | 출력 |
|----------|--------|------|------|
| `auto_doc.py` | `python -m app.scripts.auto_doc` | 입력 파일 | 5종 전체 |
| `prd_maker.py` | `python -m app.scripts.prd_maker` | 입력 파일 | PRD MD+JSON |
| `trd_maker.py` | `python -m app.scripts.trd_maker` | PRD JSON | TRD MD+JSON |
| `wbs_maker.py` | `python -m app.scripts.wbs_maker` | PRD+TRD JSON | WBS MD+JSON |
| `pro_maker.py` | `python -m app.scripts.pro_maker` | PRD+TRD+WBS JSON | 제안서 MD+JSON |
| `ppt_maker.py` | `python -m app.scripts.ppt_maker` | 제안서 JSON | PPTX |
| `doc_maker.py` | `python -m app.scripts.doc_maker` | MD 파일들 | DOCX |
| `arch_diagram.py` | `python -m app.scripts.arch_diagram` | TRD JSON | PNG |

### 8.2 의존 관계

```
prd_maker ─── trd_maker ─── wbs_maker ─── pro_maker ─── ppt_maker
                │                                          │
                └── arch_diagram                     doc_maker
```

스크립트는 이전 단계의 출력이 필요합니다. `auto_doc`은 이 순서를 자동으로 처리합니다.

### 8.3 PPT 생성 세부 사항

`ppt_maker.py`는 제안서 JSON을 `normalize_proposal_data()` 함수로 정규화한 후 python-pptx로 약 23장의 슬라이드를 생성합니다. TRD가 존재하면 `arch_diagram.py`를 호출하여 아키텍처 다이어그램을 자동 포함합니다.

## 11. 백업 및 복구

### 11.1 백업 대상

| 항목 | 경로 | 중요도 |
|------|------|--------|
| 입력 파일 | `workspace/inputs/projects/` | 높음 |
| 생성 문서 | `workspace/outputs/` | 높음 |
| 환경 설정 | `.env` | 중간 |
| 런타임 데이터 | `data/` | 낮음 |

### 11.2 백업 방법

```bash
# 전체 워크스페이스 백업
tar -czf backup_$(date +%Y%m%d).tar.gz workspace/ .env

# 출력 문서만 백업
tar -czf outputs_$(date +%Y%m%d).tar.gz workspace/outputs/
```

### 11.3 복구 방법

```bash
# 백업에서 복구
tar -xzf backup_20260306.tar.gz
```
