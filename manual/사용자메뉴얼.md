## 1. 시스템 소개

### 1.1 개요

PRD Generator는 다양한 입력 파일을 AI 파이프라인으로 분석하여 프로젝트 문서를 자동 생성하는 시스템입니다. 텍스트, 이메일, Excel, PowerPoint, 이미지 등 다양한 형식의 입력을 받아 표준화된 문서를 생성합니다.

### 1.2 생성 가능한 문서

| 문서 | 설명 | 출력 형식 |
|------|------|-----------|
| **PRD** (제품 요구사항 문서) | 기능/비기능 요구사항, 마일스톤, 성공 지표 정의 | MD, JSON |
| **TRD** (기술 요구사항 문서) | 기술 스택, 시스템 아키텍처, API 명세, DB 설계 | MD, JSON |
| **WBS** (작업 분해 구조서) | 작업 단계, 공수 산정, 일정 계획, 크리티컬 패스 | MD, JSON |
| **제안서** (Proposal) | 경영진 요약, 프로젝트 범위, 일정, 리소스 계획 | MD, JSON |
| **PPT** (프레젠테이션) | 제안서 기반 ~23장 슬라이드 | PPTX |
| **DOCX** (Word 문서) | 위 문서들의 Word 변환본 | DOCX |
| **아키텍처 다이어그램** | TRD 기반 시스템 구조도 | PNG |

### 1.3 지원 입력 형식

| 형식 | 확장자 | 설명 |
|------|--------|------|
| 텍스트 | `.txt`, `.md` | 일반 텍스트, 마크다운 문서 |
| 이메일 | `.eml` | 이메일 파일 |
| 스프레드시트 | `.xlsx`, `.xls`, `.csv` | 엑셀, CSV 데이터 |
| 프레젠테이션 | `.pptx`, `.ppt` | 파워포인트 파일 |
| 문서 | `.pdf`, `.docx`, `.doc` | PDF, Word 문서 |
| 이미지 | `.png`, `.jpg`, `.jpeg` | 이미지 파일 (OCR 처리) |
| 채팅 로그 | `.json` | 구조화된 채팅/대화 기록 |

### 1.4 문서 생성 흐름

```
입력 파일 → PRD → TRD → WBS → 제안서 → PPT
                                        → DOCX
                                        → 아키텍처 다이어그램
```

PRD가 모든 문서의 기반이 되며, 이후 문서들은 이전 단계의 출력을 참조하여 생성됩니다.

## 2. 시작하기

### 2.1 시스템 접속

- **웹 대시보드**: 브라우저에서 `http://localhost:3000` 접속
- **API 문서**: `http://localhost:8000/docs` (Swagger UI)

### 2.2 입력 파일 준비

프로젝트 요구사항이 담긴 파일을 준비합니다. 파일에는 다음 내용이 포함되면 좋습니다:

- 프로젝트 배경 및 목적
- 주요 기능 요구사항
- 대상 사용자
- 기술적 제약사항
- 일정 및 예산 관련 정보

**입력 파일 위치**: `workspace/inputs/projects/` 폴더에 파일을 넣습니다.

### 2.3 문서 생성 방법

문서를 생성하는 방법은 **2가지**입니다:

1. **웹 대시보드** - 브라우저에서 시각적으로 조작 (API 모드)
2. **CLI (명령줄)** - 터미널에서 커맨드 실행 (추천)

## 3. 웹 대시보드 사용법

### 3.1 메인 화면 (대시보드)

대시보드(`http://localhost:3000`)에 접속하면 다음을 확인할 수 있습니다:

#### 문서 통계 패널
화면 상단에 문서 유형별 개수가 표시됩니다:
- **전체**: 생성된 총 문서 수
- **PRD / TRD / WBS / 제안서 / PPT**: 유형별 문서 수

#### 필터 탭
문서를 유형별로 필터링할 수 있습니다:
- `전체` | `PRD` | `TRD` | `WBS` | `제안서` | `PPT`

#### 문서 카드
각 문서는 카드 형태로 표시되며, 다음 버튼을 제공합니다:
- **JSON** 버튼: JSON 형식으로 문서 내용 보기
- **MD** 버튼: 마크다운 형식으로 문서 내용 보기 (렌더링된 형태)
- **PPTX** 버튼: PowerPoint 파일 열기 (PPT 문서만)

#### 상단 버튼
- **테마 전환** (해/달 아이콘): 라이트/다크 모드 전환
- **새로고침**: 문서 목록 갱신
- **삭제**: 모든 생성 문서 일괄 삭제

### 3.2 파일 업로드 (API 모드)

> **참고**: 이 기능은 API 모드 전용입니다. CLI 모드에서는 `workspace/inputs/projects/`에 직접 파일을 넣습니다.

1. `/upload` 페이지로 이동합니다
2. 파일을 **드래그 앤 드롭**하거나 클릭하여 선택합니다
3. 여러 파일을 동시에 업로드할 수 있습니다
4. 파일 목록에서 불필요한 파일은 X 버튼으로 제거합니다
5. **"PRD 생성 시작"** 버튼을 클릭합니다

### 3.3 처리 진행 상황 확인

PRD 생성이 시작되면 자동으로 진행 상황 페이지로 이동합니다:

```
Layer 1: 파싱      ─ 파일에서 텍스트 추출
Layer 2: 정규화    ─ 요구사항 분류 (FR/NFR/제약조건)
Layer 3: 검증      ─ 품질 확인 및 신뢰도 평가
Layer 4: 생성      ─ PRD 문서 작성
```

- 각 단계의 진행 상태가 실시간으로 표시됩니다
- 처리 완료 시 자동으로 PRD 상세 페이지로 이동합니다

### 3.4 PM 리뷰

신뢰도가 80% 미만인 요구사항이 있으면 PM 리뷰 페이지로 이동됩니다:

1. 각 항목의 **이슈 유형**을 확인합니다 (낮은 신뢰도, 모호함, 불완전, 충돌, 정보 부족)
2. 항목을 클릭하여 상세 내용을 확인합니다
3. 각 항목에 대해 결정을 내립니다:
   - **승인**: 현재 내용 그대로 사용
   - **거부**: 해당 요구사항 제외
   - **수정**: 내용 수정 후 반영
4. 메모를 추가할 수 있습니다 (선택사항)
5. **"결정 제출"** 버튼으로 제출합니다
6. 모든 항목 검토 후 **"검토 완료"** 버튼을 클릭합니다

### 3.5 PRD 상세 보기

생성된 PRD는 4개 탭으로 구성됩니다:

| 탭 | 내용 |
|----|------|
| **개요** | 배경, 목표, 범위, 대상 사용자, 성공 지표 |
| **요구사항** | 기능(FR), 비기능(NFR), 제약조건 - 각 항목의 우선순위, 신뢰도, User Story, 인수 조건 포함 |
| **마일스톤** | 프로젝트 단계별 산출물 |
| **미해결** | 추가 확인이 필요한 질문, 결정사항, 리스크 |

상단 버튼으로 **MD** 또는 **JSON** 형식으로 내보내기할 수 있습니다.

### 3.6 PRD 히스토리

`/history` 페이지에서 생성된 모든 PRD를 관리합니다:
- 검색: 제목으로 PRD 검색
- 내보내기: Markdown / JSON / HTML 형식으로 다운로드
- 삭제: 개별 PRD 삭제
- 페이지네이션: 10개 단위로 페이지 이동

## 4. CLI 사용법

### 4.1 입력 파일 배치

프로젝트 요구사항 파일을 다음 폴더에 넣습니다:

```
workspace/inputs/projects/
```

### 4.2 전체 문서 일괄 생성

가장 간편한 방법으로, PRD부터 PPT까지 모든 문서를 순차적으로 생성합니다:

```bash
python -m app.scripts.auto_doc
```

생성 순서: PRD → TRD → WBS → 제안서 → PPT

### 4.3 개별 문서 생성

필요한 문서만 선택적으로 생성할 수 있습니다:

```bash
# PRD 생성 (입력 파일 기반)
python -m app.scripts.prd_maker

# TRD 생성 (최신 PRD 기반)
python -m app.scripts.trd_maker

# WBS 생성 (최신 PRD + TRD 기반)
python -m app.scripts.wbs_maker

# 제안서 생성 (최신 PRD + TRD + WBS 기반)
python -m app.scripts.pro_maker

# 제안서 생성 (고객사명 지정)
python -m app.scripts.pro_maker --client "ABC 주식회사"

# PPT 생성 (최신 제안서 기반, ~23 슬라이드)
python -m app.scripts.ppt_maker

# 아키텍처 다이어그램 생성 (최신 TRD 기반)
python -m app.scripts.arch_diagram
```

### 4.4 DOCX 변환

생성된 마크다운 문서를 Word 파일로 변환합니다:

```bash
# 전체 변환 (PRD + TRD + WBS + 제안서)
python -m app.scripts.doc_maker

# 개별 변환
python -m app.scripts.doc_maker --type prd
python -m app.scripts.doc_maker --type trd
python -m app.scripts.doc_maker --type wbs
python -m app.scripts.doc_maker --type proposal
```

### 4.5 출력 파일 위치

생성된 문서는 다음 폴더에 저장됩니다:

```
workspace/outputs/
├── prd/           # PRD (MD + JSON)
├── trd/           # TRD (MD + JSON)
├── wbs/           # WBS (MD + JSON)
├── proposals/     # 제안서 (MD + JSON)
├── ppt/           # PPT (PPTX)
├── doc/           # Word (DOCX)
└── diagrams/      # 아키텍처 다이어그램 (PNG)
```

**파일 이름 규칙**: `{문서유형}-{YYYYMMDD-HHMMSS}.{확장자}`

예: `PRD-20260306-143022.md`, `PPT-20260306-143530.pptx`

## 5. 문서 유형별 안내

### 5.1 PRD (제품 요구사항 문서)

**입력**: `workspace/inputs/projects/`의 파일들
**출력**: MD + JSON

PRD에 포함되는 내용:
- **개요**: 프로젝트 배경, 목표, 범위, 범위 외 항목
- **대상 사용자**: 주요 사용자 그룹
- **성공 지표**: 프로젝트 성공을 측정하는 KPI
- **기능 요구사항 (FR)**: 시스템이 제공해야 할 기능
- **비기능 요구사항 (NFR)**: 성능, 보안, 확장성 등
- **제약조건**: 기술적/비즈니스적 제한사항
- **마일스톤**: 프로젝트 단계 및 산출물
- **미해결 항목**: 추가 논의가 필요한 사항

각 요구사항에는 **신뢰도 점수**(0~100%)가 부여됩니다. 80% 이상이면 자동 승인, 미만이면 PM 리뷰가 필요합니다.

### 5.2 TRD (기술 요구사항 문서)

**입력**: 최신 PRD JSON
**출력**: MD + JSON

TRD에 포함되는 내용:
- **기술 스택**: 프론트엔드, 백엔드, DB, 인프라 기술 선정 및 근거
- **시스템 아키텍처**: 전체 구조, 컴포넌트 간 관계
- **데이터베이스 설계**: 테이블 구조, 관계, 인덱스
- **API 명세**: 엔드포인트, 요청/응답 형식, 인증 방식

### 5.3 WBS (작업 분해 구조서)

**입력**: 최신 PRD + TRD JSON
**출력**: MD + JSON

WBS에 포함되는 내용:
- **프로젝트 단계**: 기획, 설계, 개발, 테스트, 배포 등
- **작업 패키지**: 각 단계의 세부 작업
- **태스크**: 작업 패키지의 구체적 실행 항목
- **공수 산정**: 작업별 예상 소요 시간 (시간/인월)
- **크리티컬 패스**: 프로젝트 최장 경로

### 5.4 제안서 (Proposal)

**입력**: 최신 PRD + TRD + WBS JSON
**출력**: MD + JSON

제안서에 포함되는 내용:
- **경영진 요약**: 프로젝트 핵심 가치 요약
- **프로젝트 범위**: 수행 범위 및 제외 사항
- **타임라인**: 전체 일정 계획
- **리소스 계획**: 필요 인력 및 역할 배분
- **기대 효과**: 프로젝트 도입으로 얻는 가치

### 5.5 PPT (프레젠테이션)

**입력**: 최신 제안서 JSON (+ TRD가 있으면 아키텍처 다이어그램 포함)
**출력**: PPTX (~23장)

슬라이드 구성:
1. 표지
2. 목차
3. 경영진 요약 (2장)
4. 현재 상황 섹션 (4장)
5. 프로젝트 목표 섹션 (2장)
6. 솔루션 섹션 (4장)
7. 일정 계획 섹션 (4장)
8. 기대 효과
9. 다음 단계
10. Q&A

### 5.6 DOCX (Word 문서)

**입력**: 각 문서의 MD 파일
**출력**: DOCX

PRD, TRD, WBS, 제안서를 Word 형식으로 변환합니다. 서식, 표, 목록이 포함된 전문적인 문서로 출력됩니다.

## 6. 자주 묻는 질문 (FAQ)

### Q1. 입력 파일은 어떤 형식이 가장 좋나요?

텍스트(.txt) 또는 마크다운(.md) 형식이 가장 정확한 결과를 생성합니다. 요구사항이 구조적으로 정리되어 있을수록 좋습니다. Excel 형식도 요구사항이 행/열로 정리되어 있으면 효과적입니다.

### Q2. 여러 파일을 동시에 입력할 수 있나요?

네. `workspace/inputs/projects/` 폴더에 여러 파일을 넣으면 모두 분석하여 하나의 PRD를 생성합니다. 웹 업로드에서도 복수 파일을 동시에 업로드할 수 있습니다.

### Q3. 문서 생성에 얼마나 걸리나요?

입력 파일의 크기와 복잡도에 따라 다르지만, 일반적으로:
- PRD: 1~3분
- TRD/WBS/제안서: 각 1~2분
- PPT: 30초~1분
- 전체(auto_doc): 5~10분

### Q4. PM 리뷰는 언제 발생하나요?

AI가 요구사항을 분석할 때 신뢰도가 80% 미만인 항목이 있으면 PM 리뷰로 라우팅됩니다. 모호하거나 불완전한 요구사항, 충돌하는 내용 등이 해당됩니다.

### Q5. 이전에 생성한 문서를 다시 볼 수 있나요?

네. 웹 대시보드 메인 화면에서 모든 생성 문서를 확인할 수 있습니다. 또는 `workspace/outputs/` 폴더에서 직접 파일을 열 수도 있습니다.

### Q6. 특정 문서만 다시 생성하고 싶어요.

CLI에서 개별 스크립트를 실행하면 됩니다. 예를 들어, 제안서만 다시 생성하려면:

```bash
python -m app.scripts.pro_maker
```

### Q7. 문서를 모두 삭제하고 처음부터 시작하려면?

```bash
# 생성된 문서만 삭제
# workspace/outputs/ 내 파일 삭제

# 입력 파일도 함께 삭제
# workspace/inputs/projects/ 내 파일도 삭제
```
